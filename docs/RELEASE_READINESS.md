# قائمة جاهزية الإصدار — عالمنا الخاص

هذه القائمة تفصل بين ما ينجح في المصدر وCI، وما يحتاج إلى إعداد خارجي أو تجربة فعلية. لا تعتبر النسخة إصداراً نهائياً قبل إغلاق البوابات أدناه.

## بوابة صلاحية المالك الخاصة

- [ ] تصميم وتنفيذ صلاحية المالك الخاصة التي طلبها المستخدم، بحيث تفتح المشاهد الـ21 والمحتوى المقفل وتسمح بفتح مشهد لشخص آخر.
- [ ] اعتماد تحقق آمن لا يضع الرمز الرئيسي أو سرّاً ثابتاً داخل APK أو مستودع Git؛ يجب أن تكون الصلاحية قابلة للتحقق عبر آلية موثوقة ومحمية، لا مجرد تجاوز محلي يمكن استخراجه من التطبيق.
- [ ] اختبار الصلاحية على نسختين من التطبيق والأجهزة المختلفة، مع التأكد من عدم منحها للعضو العادي أو تسريب الرمز.

## بوابة الخلفية السحابية

- [ ] إنشاء مشروع Supabase فعلي، مع الاحتفاظ بكلمة مرور قاعدة البيانات خارج المستودع.
- [ ] تفعيل تسجيل الدخول المجهول (Anonymous Auth).
- [ ] تطبيق migrations من 001 إلى 010 بالترتيب الوارد في [دليل النشر](SUPABASE_DEPLOYMENT.md).
- [ ] التأكد من وجود الحاوية الخاصة `world-media` وسياسات RLS/RPC كما يشرح الدليل.
- [ ] إعداد `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` فقط في Gradle properties المحلية أو GitHub Actions secrets.
- [ ] عدم إدخال `service_role` أو كلمة مرور قاعدة البيانات أو أي مفتاح إداري في التطبيق أو المستودع.

## بوابة اختبار جهازين

- [ ] إنشاء العالم من الجهاز الأول، وإرسال طلب الاقتران من الثاني، ثم الموافقة من المالك.
- [ ] التأكد من أن الطلب غير الموافق عليه لا يفتح العالم، وأن كل جهاز يستلم غلاف مفتاحه الخاص.
- [ ] اختبار إضافة وتعديل الذكريات والرسائل والرسم والحديقة والإجابات اليومية والكبسولات من كلا الجهازين.
- [ ] اختبار رفع صورة ومعاينتها وحذفها، والتأكد من وصول الحذف إلى الجهاز الآخر.
- [ ] اختبار العمل دون اتصال ثم إعادة الاتصال، مع إغلاق التطبيق وإعادة تشغيله أثناء وجود تعديلات معلقة.
- [ ] إلغاء عضوية جهاز، والتحقق من رفض عمليات القراءة والرفع والحذف الجديدة عليه.
- [ ] مراجعة اختلاف التوقيت بين الجهازين والتأكد من تطابق سؤال اليوم والمفاجأة والعداد.
- [ ] توثيق أي تعارض أو فقد أو تكرار، وإصلاحه قبل قبول النسخة.

## بوابة الإصدار

- [ ] نجاح أحدث Android CI: اختبارات الوحدة، فحص migrations، بناء APK، تدقيق أسرار الحزمة، ورفع artifact.
- [ ] مراجعة سياسة الخصوصية وإكمال بيانات جهة التواصل وآلية حذف البيانات قبل النشر.
- [ ] ضبط اسم التطبيق والأيقونة ورقم الإصدار النهائي.
- [ ] إنشاء مفتاح توقيع إصدار محفوظ خارج Git، وعدم مشاركة ملفه أو كلمة مروره.
- [ ] بناء APK/AAB موقّع للإصدار، ثم تثبيته واختباره على جهاز فعلي.
- [ ] الاحتفاظ بنسخة من ملف الإصدار ومعلومات البناء وملاحظات الإصدار.

## الحالة الحالية

المصدر يحتوي على مسارات المزامنة المشفرة والاقتران وإدارة العضوية والألبوم، وقد اجتازت أجزاء منها بناء CI واختبارات الوحدة. لكن إنشاء مشروع Supabase وتطبيق migrations واختبار جهازين فعليين وإعداد توقيع الإصدار ما زالت بوابات خارجية غير منجزة. لا يثبت نجاح CI وحده تشغيل الخدمة السحابية أو سلامة تجربة الجهازين.
